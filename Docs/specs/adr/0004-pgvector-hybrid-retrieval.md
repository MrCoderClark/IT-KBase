# ADR 0004 — pgvector + embeddings for AI Assistant retrieval

- **Status:** Accepted
- **Date:** 2026-11-02
- **Branch:** `feat/assistant-ask-kb`

## Context

The AI Assistant (`Docs/specs/20-ai-assistant.md`) answers only from KB articles the user may read, with citations. Answer quality depends on retrieval.

Postgres full-text search (`Article.searchVector`, ADR 0003 "Search (v1)") is strong on the exact tokens IT staff type — error codes (`0x80180014`), KB IDs, cmdlet names — but misses paraphrased questions ("laptop won't let me sign in after a password change" vs "Resetting the Local Administrator Password").

The spec originally deferred vector search to phase AI-5. The decision on 2026-11-02 was to ship **hybrid retrieval in AI-1**. ADR 0003 requires an ADR for additions to the locked stack.

## Decision

### Vector store: pgvector in the existing Postgres

- Extension **pgvector 0.8.7** in database `aw_it_kbase`. No separate vector database (Pinecone, Qdrant, Weaviate, Redis vector search).
- Install and verification runbook: `infra/pgvector/README.md`.
- Dev/pilot server (Windows, PostgreSQL 18.0) uses the **unofficial prebuilt binary** from `andreiramani/pgvector_pgsql_windows` (PostgreSQL 18 asset). Production should use a build from the official source or a managed Postgres that ships pgvector.
- The Prisma migration runs `CREATE EXTENSION IF NOT EXISTS vector`. The extension is not declared through Prisma's `postgresqlExtensions` preview feature (keeps the generator config unchanged).

### Unit of retrieval: section-level chunks

- New table `ArticleChunk`: one row per article section's prose, and one row per code block (kept whole, never split).
- Each row holds plain `text`, a `searchVector` (tsvector, maintained by trigger), and `embedding vector(1536)` (nullable until the embedding job fills it).
- Chunks are built from the article's `currentVersionId`, the same version `Article.searchVector` indexes. Access is enforced at query time by joining `Article` (status rules + per-page access, spec 12), never by what is stored.
- `contentHash` (SHA-256 of chunk text + embedding model) lets a reindex reuse embeddings for unchanged chunks.

### Index

- HNSW with `vector_cosine_ops` on `ArticleChunk.embedding`.
- GIN on `ArticleChunk.searchVector`.

### Embeddings

- Generated by the **FastAPI** service (`claude.md` non-negotiable 8: Python owns LLM calls) with an OpenAI-compatible client.
- **Separate configuration from ingestion.** The assistant uses its own `ASSISTANT_*` settings (`AssistantSettings` in `backend/src/backend/config.py`): `ASSISTANT_BASE_URL`, `ASSISTANT_API_KEY`, `ASSISTANT_CHAT_MODEL`, `ASSISTANT_EMBEDDING_MODEL`, `ASSISTANT_EMBEDDING_DIMENSIONS`. The ingestion `AI_*` settings and the extractor are unchanged; there is no fallback between the two.
- Default embedding model `openai/text-embedding-3-small` via OpenRouter `POST /api/v1/embeddings`, **1536 dimensions**.
- Next.js never calls the embeddings API directly.

### Ranking

- Keyword (chunk `searchVector`) and vector (cosine distance) result lists merged with **Reciprocal Rank Fusion**, plus an exact-token boost for error codes and KB IDs. Implemented in one SQL query in the Next.js BFF so the existing visibility rules apply in the same statement.

## Consequences

- **Changing the embedding model or dimensions** requires a migration (new column type) and a full re-embed. `embeddingModel` on each row records what produced it; mixed models must never be compared.
- **Database portability:** every TechBase Postgres (dev, CI, prod) needs pgvector. CI that runs migrations must use an image with pgvector (for example `pgvector/pgvector:pg18`).
- **Windows server upgrades:** after a PostgreSQL major upgrade, pgvector must be reinstalled for the new major before the database is used (`infra/pgvector/README.md` §5).
- **Cost:** embeddings are billed per token. Articles are re-embedded only when a chunk's `contentHash` changes. A full backfill of the current library is a one-off.
- **Prisma:** `embedding` and `searchVector` are `Unsupported(...)` fields. Prisma writes chunk rows; the embedding is written with raw SQL. Vector queries use `$queryRaw`.
- Spec 20 §5.2 and §12 are updated: hybrid retrieval moves from AI-5 into AI-1.

## Alternatives considered

| Option | Why not |
|--------|---------|
| FTS only in AI-1, vectors in AI-5 | Paraphrased questions are common from helpdesk L1; the decision was to cover them from the first release. |
| Separate vector DB (Qdrant, Pinecone) | Second datastore to secure and back up; breaks single-statement permission filtering. |
| Redis vector search | The running Redis is the plain image; permission filtering would still need Postgres. |
| Embeddings computed in Next.js | Violates the "Python owns LLM calls" rule and splits provider config across two services. |
| Article-level (not section-level) embeddings | Too coarse for citations that deep-link to a section. |
